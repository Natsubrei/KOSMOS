# 翻译规则

[English](translation-rules.md) | 中文

怎么写一对文档的另一侧。任一侧都可以先写，该侧就是这次的源。[terminology.md](terminology.md) 管每个词怎么写；[glossary.zh.md](../glossary.zh.md) 管词是什么意思。本规则约束人和 agent。配对门禁不执行这些规则。

## 忠实

对侧说的就是源侧说的：不增添行为、警告或例子，也不删减。两边实质不一致时，改错的那侧，再在同一次变更里带上另一侧。译意思，不要逐词对译；原文简就保持简。

## 语气

英文是简短的专业开发者散文。中文是书面技术中文。不要移植比喻。目标语言会把动作发出者藏起来时，把发出者写出来。称呼读者用「你」，不用「您」。

## 结构

章节按位置配对（标题数相同、顺序相同）。标题文本可以翻译。围栏代码块连注释在内字节级一致。行内代码、URL、标识符保持 ASCII 原文，不翻译、不重排格式。相对链接指向同一目标；成对文档的中文侧在对侧存在时指向 `.zh.md`。配对门禁检查章节哈希和相对链接。列表形态、表格形态、标题深度归人审；不要为它们加扫描器。

## 术语

改 `.zh.md` 之前加载 [terminology.md](terminology.md)。表中每个词遵守该行和「不要译作」。不要当场发明译法；定下来的词在同一次变更里加行。未收录的技术术语：没有可引用的通行中文译法就留英文。

## 排版

以下管中文侧。英文侧按普通 Markdown。

- 中文与拉丁词之间、中文与数字之间各留一个半角空格：`每个 agent 采集 3 类 Record`。全角标点与任何字符之间不加空格。
- 中文正文用全角标点：`，。：；？！（）「」`。半角标点留在代码里（`` `Subscribe(cpu)` ``、`` `{id, start, end}` ``）、按原样引用的完整英文句子里、以及数字里（`3.5`、`1,024`）。
- 中文并列用顿号（`、`），不用逗号。
- 不用全角数字或全角拉丁字母。
- 不要对 `.zh.md` 整行跑标点转换；它会改掉反引号里的标识符。

## 质量

任一侧重读都能得到同样的事实、同样的限定、同样的语气，且没有多出来的东西，这对才算完成。`scripts/verify-translation-pair.sh` 检查哈希和结构。绿的配对哈希不证明译法、术语、标点或空格。不要为这些加扫描器。
